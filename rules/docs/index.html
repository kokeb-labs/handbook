KB-DOC-001: Markdown passes the org lint configuration¶

MUST · all · since 1.0

Every Markdown file passes markdownlint-cli2 with the org configuration.

Verified by:

  • markdownlint/all (implemented): markdownlint-cli2 with the org config; the parameter names the rule (markdownlint/MD040)

KB-DOC-002: The documentation site builds strictly¶

MUST · driver, library, hal, tooling, docs, template · since 1.0

A repository with a documentation site builds it with mkdocs --strict: no broken internal link, no page left out of the navigation.

Verified by:

  • mkdocs-strict (implemented): the documentation site builds with mkdocs --strict (no broken internal link, every page in the nav)

Explained in: standards/docs.md

KB-DOC-003: No broken links on the built site¶

MUST · driver, library, hal, tooling, docs, template · since 1.0

Every link on the built site resolves, internal and external.

Verified by:

  • link-check (implemented): lychee finds no broken link on the built site

KB-DOC-004: Every public API is documented and Doxygen is warning-free¶

MUST · driver, library, hal, template · since 1.0

Every public type, function and parameter in inc/ has a Doxygen comment; Doxygen runs with WARN_IF_UNDOCUMENTED = YES and WARN_AS_ERROR = FAIL_ON_WARNINGS.

Verified by:

  • doxygen-warnings (implemented): Doxygen with WARN_AS_ERROR = FAIL_ON_WARNINGS and WARN_IF_UNDOCUMENTED reports nothing

Explained in: standards/docs.md

KB-DOC-005: Every public repository publishes a versioned MkDocs site¶

MUST · driver, library, hal, firmware, tooling, docs, template · since 1.0

Every public repository publishes its documentation at https://kokeb-labs.github.io/<repo>/ through ru-mkdocs-publish, built with kokeb-mkdocs-theme and versioned per v* tag; a code repository merges its Doxygen reference under api/. A -rc tag publishes its version without moving the latest alias.

Why: One platform and one theme mean a reader finds the same layout on every site, and a pinned version per tag means the page a user reads matches the code they built.

Verified by:

  • mkdocs-strict (implemented): the documentation site builds with mkdocs --strict (no broken internal link, every page in the nav)
  • review: The docs workflow calls ru-mkdocs-publish and the site is live at kokeb-labs.github.io/<repo>/.

Explained in: standards/docs.md

KB-DOC-006: Pages live in docs/ and the site config in _config/mkdocs.yml¶

MUST · driver, library, hal, firmware, tooling, docs, template · since 1.0

Pages live in docs/. The site configuration is _config/mkdocs.yml with docs_dir: ../docs, and the docs workflow is passed mkdocs_config: _config/mkdocs.yml and, in a code repository, doxygen_config: _config/Doxyfile.

Verified by:

  • mkdocs-strict (implemented): the documentation site builds with mkdocs --strict (no broken internal link, every page in the nav)
  • review: The docs workflow passes mkdocs_config and doxygen_config with the _config/ paths.

See also: ADR-0011

Explained in: standards/docs.md

  • docs-nav (planned): docs/.nav.yml has exactly the five tabs Home, Get started, Concepts, Guides, Reference in order, and contract.md sits under Concepts right after Architecture

KB-DOC-008: The site has the page set for its kind¶

Proposed

Warns until 2027-03-01, then fails CI.

MUST · driver, library, hal, firmware, tooling, template · since 1.0 · enforced from 2027-03-01

docs/ holds every page the documentation standard lists for the repository's kind (driver, standalone library, kb-core, HAL, product, CI and tools). A page that cannot apply, such as Configuration for a driver with no Config, is left out rather than kept empty.

Why: A fixed page set lets a reader move between repositories without relearning where things are, and lets a check say what is missing.

Verified by:

  • docs-page-set (planned): docs/ has every page the documentation standard requires for the repository's declared kind, and each is in the navigation

Explained in: standards/docs.md

KB-DOC-010: The Contract page has the standard sections in order¶

Proposed

Warns until 2027-03-01, then fails CI.

MUST · driver, library, hal, firmware, template · since 1.0 · enforced from 2027-03-01

docs/contract.md has the sections Promises, Depends on, Threading, Errors, Memory, Platform and Deviations from the standard, in that order, after a one-line purpose.

Why: The Contract is the short normative summary a caller or an auditor reads first; fixed sections make a missing promise visible.

Verified by:

  • heading-skeleton/contract (planned): a Markdown file's headings match a required skeleton in order (parameter: contract, readme, adr, hf-hal-readme, hf-board-spec, hf-protocol-spec)

See also: IEC 62304:2006+A1:2015 5.4.3 (detailed design of software unit interfaces)

Explained in: standards/docs.md

KB-DOC-011: The Contract page lists every handbook rule the repository does not meet¶

MUST · driver, library, hal, firmware, template · since 1.0

The Deviations section names, by rule ID, each handbook rule the repository does not meet yet, with its issue or waiver. An empty section says "None".

Verified by:

  • review: Every waiver in .kokeb/handbook.yml and every known unmet rule appears in the Deviations section with its issue.

Explained in: deviations.md

KB-DOC-012: Repository docs link the handbook instead of restating it¶

SHOULD · all · since 1.0

The handbook is the single source of the rules. A repository's docs, Contract page, templates and CI link the rule they follow and state only what is specific to the repository; no repository keeps a copy of the handbook or of its pages.

Why: A copied rule drifts from the original the first time either is edited.

Verified by:

  • review: No page restates a handbook rule that it could link; no vendored copy of handbook pages.

Explained in: standards/docs.md

KB-DOC-013: CONTRIBUTING.md links the handbook¶

SHOULD · all · since 1.0

A repository's CONTRIBUTING.md, or the organisation default it inherits, links the handbook. AGENTS.md links it as KB-AGT-005 requires.

Verified by:

  • review: CONTRIBUTING.md (own or the org default) links kokeb-labs.github.io/handbook.

KB-DOC-014: A change to behaviour or API updates its docs in the same pull request¶

SHOULD · all · since 1.0

A pull request that changes behaviour, the public API, a pin, a default or a build option updates the README, the pages under docs/ and the CHANGELOG entry that describe it, in the same pull request.

Why: Docs updated later are docs that are wrong in between, and usually stay wrong.

Verified by:

  • docs-touched (planned): warns when a pull request changes inc/, a Kconfig or a CMake option without touching README.md, docs/ or CHANGELOG.md
  • review: Every page that describes the changed behaviour is updated in this pull request.

KB-DOC-015: The README has the standard sections in order¶

Proposed

Warns until 2027-03-01, then fails CI.

SHOULD · driver, library, hal, firmware, tooling, template · since 1.0 · enforced from 2027-03-01

The README has, in order and only where they apply: title and hero line, true badges, the bold docs link, a plain-language paragraph, one figure, At a glance (with the status), Datasheet, Try it on your PC, Use it on your MCU, What it does, Install, Documentation (with "Read it when you want to"), Tests and quality, License.

Verified by:

  • heading-skeleton/readme (planned): a Markdown file's headings match a required skeleton in order (parameter: contract, readme, adr, hf-hal-readme, hf-board-spec, hf-protocol-spec)

Explained in: standards/docs.md

KB-DOC-016: The README is short and leaves the reference to the site¶

SHOULD · all · since 1.0

A README has no table of contents, no emoji walls, no check-mark feature lists, no badge that links nowhere or states something untrue, and no API tables that duplicate the site.

Verified by:

  • prose-style/emoji (planned): Vale with the Kokeb style; the parameter names the style rule
  • review: The README has none of the banned elements and every badge is live and true.

Explained in: standards/docs.md

KB-DOC-017: A driver's README names the chip and the part, not the organisation¶

MUST · driver, template · since 1.0

A driver's README and site name the chip and part it drives; the organisation appears only in links and the licence line, so the driver reads as usable on its own.

Verified by:

  • forbidden-patterns/readme-org-name (planned): a source scan for a construct the handbook bans; the parameter names the pattern set
  • review: The README names the chip and part; no Kokeb Labs or HardFOC branding outside links.

See also: ADR-0012

Explained in: standards/docs.md

KB-DOC-018: The README licence line matches LICENSE and the package metadata¶

MUST · all · since 1.0

The README's License line, LICENSE and every package manifest (idf_component.yml, library.json and the like) name the same licence: MIT for code, CERN-OHL-P-2.0 for a hardware design.

Verified by:

  • review: README License line, LICENSE and package manifests name the same licence.

See also: ADR-0009

KB-DOC-019: A family driver is named after the member it was written for¶

SHOULD · driver · since 1.0

A driver that covers a chip family is named after the part it was written and tested for; the README lists the other members it supports and how far each is tested.

Verified by:

  • review: The repository name is the tested part; the README lists the other family members and their status.

Explained in: standards/driver.md

KB-DOC-020: Every C++ block on the site compiles¶

MUST · driver, library, hal, template · since 1.0

A C++ snippet longer than one line lives in tests/docs/*.cpp between --8<-- section markers, is built by the host build with warnings on, and is included in the page; it is never pasted inline.

Why: An example that does not compile teaches the wrong API, and nobody notices until a user pastes it.

Verified by:

  • host-tests (implemented): the unit tests build and pass on the host with gcc and clang
  • docs-inline-code (planned): no C++ fence longer than one line in docs/ or README.md is written inline; each comes from tests/docs via a --8<-- include or a generated region

Explained in: standards/docs.md

KB-DOC-021: Examples check every result¶

MUST · driver, library, hal, firmware, template · since 1.0

Every example on the site and in the README checks each Result and Status it gets and shows what to do with an error; no example ignores a return value or elides code with // ....

Verified by:

  • compiler-warnings/-Wunused-result (implemented): the build is warning-free with the named flag and -Werror
  • review: Each example handles every returned Result or Status.

Explained in: standards/docs.md

KB-DOC-022: Generated regions and figures match the code¶

Proposed

Warns until 2027-03-01, then fails CI. ru-mkdocs-publish runs the drift check today; once its job is named in the registry the check is implemented and this rule can be active.

MUST · driver, library, hal, firmware, template · since 1.0 · enforced from 2027-03-01

The README quickstart, examples lists and figures are generated regions (kokeb-docs), and CI fails when one no longer matches the code it is generated from. kokeb-docs check runs the same check locally.

Verified by:

  • docs-drift (planned): kokeb-docs check finds no generated region (README quickstart, examples list) or figure that differs from what the code generates

Explained in: standards/docs.md

KB-DOC-023: The Porting page shows a complete, compiled port for each bus¶

MUST · driver, template · since 1.0
