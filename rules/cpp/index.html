KB-CPP-001: C++20, no compiler extensions¶

MUST · driver, library, hal, firmware, template · since 1.0

Code is written in ISO C++20 and builds with CMAKE_CXX_STANDARD 20, CMAKE_CXX_STANDARD_REQUIRED ON and CMAKE_CXX_EXTENSIONS OFF. Features beyond C++20 are not used.

Why: One language level across the stack lets any driver sit under any library. C++20 gives concepts and constexpr enough for zero-cost ports without the toolchain lag of C++23 on vendor compilers. Which C++20 features are used, and under which rules, is the C++20 profile (KB-CPP20-001 to 058).

Verified by:

  • compiler-warnings/-Wpedantic (implemented): the build is warning-free with the named flag and -Werror
  • forbidden-patterns/cmake-cxx-standard (implemented): a source scan for a construct the handbook bans; the parameter names the pattern set

KB-CPP-002: No exceptions and no RTTI¶

KB-CPP-003: No heap in drivers; no heap after start-up anywhere¶

KB-CPP-124: Start-up waits for the chip's own ready indication, bounded by a Config deadline¶

Proposed

Warns until 2027-03-01, then fails CI. Works with KB-CPP-080 and KB-CPP-114.

MUST · driver, template · since 1.0 · enforced from 2027-03-01

Start-up waits for the chip's own ready indication: first the datasheet minimum, then a bounded poll of the ready, busy or ID bit with a deadline from Config. A fixed delay alone is not enough, a correct ID is not readiness, and a delay never returns early. An expired deadline returns Timeout or NotReady.

Why: Observed on hardware: chips answered their ID before they were ready, and the wake time varied with the supply ramp by more than ten times.

Verified by:

  • model-virtual-clock (planned): a chip model for a driver whose port has DelayUs or DelayMs advances a virtual clock in those hooks, and a test runs a delayed-ready mode against it
  • review: A model with a virtual clock and a delayed-ready mode shows the driver neither returns early nor waits past its deadline.

See also: NASA/JPL Power of Ten Rule 2 (fixed upper bound on loops)

KB-CPP-126: Values are checked against the operating range and never silently clamped¶

Proposed

Warns until 2027-03-01, then fails CI.

Arguments and Config fields are checked against the datasheet's operating range, not the register's range, and a value outside it returns InvalidArgument; nothing is silently clamped.
